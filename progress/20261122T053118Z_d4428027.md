# 2026-11-22 — feature #113: certify checks only the reasons conflict analysis used

Session d4428027 (feature).

## Measurement (instrumented build, not committed; 16 fresh permuted copies each of hole8/hole9)

- `certify` before the change: 5.9 % of `cdcl` time on hole9 copies (1066 ns per conflict), 7.5 % on
  hole8. `force_trail` visits 66 trail entries per conflict (hole9), but only 12.6 reasons are needed
  (backward closure from the conflict clause); `reason_ok` cost is dominated by branch mispredicts
  and by cold clause memory, not by the walk alone.
- Variants tried (same trajectory each): (a) `used[v] == epoch` mark per variable + full trail walk:
  −0.7 to −2.4 %; (b) + walk from the lowest touched level: −2.3 %; (c) branch-free conditions:
  slower; (d) `reason_ok` over a clause reference: no gain; (e) explicit hint list: −2.3 %;
  (f) (e) + mark buffer kept in `Search`: −2.9 to −3.5 %. (f) is the committed design.

## Design (core/src/lib.rs)

- `Search.hint`: the variables analysis resolved on (first `nres`, from the last trail position down),
  then the variables `minimize` found redundant (pushed when their frame pops). Untrusted.
- `Search::certify` (now a method): `mark` into `cleared(marks)` (the kept buffer, all cleared; a new
  vector if its length differs or the fuel ran out), force the level-0 trail prefix (`force_trail`
  up to `lo = lim[0]`), the redundant variables in passes until no pass both forces one and leaves
  one (`force_fix`/`force_pass`; minimisation order is not topological across literals), then the
  resolved variables in trail order (`force_back`); `force_var` skips marked variables. The buffer
  goes back into `marks`. Soundness does not depend on the hint: a wrong hint only fails the check.
- Mutable flags are `usize` (a `bool` mutable local adds a prism to the locale).

## Proofs

- `Sat_Certify`: contracts for `cleared`, `mark` (takes the buffer), `force_var`, `force_trail`,
  `force_pass`, `force_fix`, `force_back`; all carry `rvec_wf` of the mark vector. `certify`'s
  contract moved to `Sat_CDCL` as `Search_certify_contract` (same entailment, plus `sok`).
- `sok` gains `vok L8 (Search_hint s)` and `rvec_wf (Search_marks s)`; `sok_learnt_reset` covers
  `hint.clear()`; `new_search` uses `from_elem_wf`.
