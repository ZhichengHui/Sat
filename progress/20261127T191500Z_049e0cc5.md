## Change

- `Search` gains `heap`/`hpos`/`hlen` (fixed-length vectors, so `sok` is unchanged; every index is
  guarded) and `use_heap`.
  - The heap is a binary max-heap keyed on (activity desc, index asc), the exact order of the old
    scan (strict `>`, lowest index wins). So every decision is the same as main's, ties included.
  - Checked: byte-identical output to main on the 102 suite instances, all 208 permuted copies
    (with the heap forced on, `HEAP_MIN = 0`) and the 15 bmc/hanoi instances.
- MiniSat scheme:
  - `pick` pops until it finds an unassigned variable;
  - `backtrack` reinserts the variables it unassigns (`reinsert`, before the old loop);
  - `bump` calls `sift_up`, and `rescale` rebuilds the heap (`heapify`), since the shift can make
    activities equal.
- **`HEAP_MIN = 512`**: below it `pick` keeps the linear scan (`pick_scan`) and the heap is unused.
  An always-on heap was 3–5 % slower on uuf100/hole copies (100/90 variables); hanoi4 (718
  variables) was neutral. The always-on version (commit 1ade654) is still in the branch history.
- **`#[inline(never)]`** on `sift_up`, `heapify`, `reinsert`, `pick_heap`.
  - Without it, the heap code inlined into `bump`/`backtrack`/`cdcl` changed the code generated
    for `cdcl`: +1.4 % instructions on hole9, even with the heap off.
  - With it, hole9 runs 0.10 % *fewer* instructions than main (all 16 fresh copies lower).
  - The front end ignores the attribute (the translation is unchanged).
- Proofs:
  - New theory `proof/Sat_Heap.thy` (281 lines, between `Sat_Vectors` and `Sat_Search`): no-panic
    plus `sok` contracts for `before`, `sift_up`, `sift_down`, `heapify`, `insert`, `reinsert`,
    `heap_pop`, `pick_scan` (the old `pick` proof), `pick_heap`, `pick`, `iota`.
  - `Sat_Search`: `rescale`/`bump`/`backtrack`/`new_search` use them.
    - `new_search` needs `HEAP_MIN_def` inlined.
    - `backtrack`'s `if use_heap { reinsert }` gives two loop goals: `apply (all ‹ucincl_discharge…›)`.
  - `Sat_CDCL` is unchanged: `crush_base` took the new `Search_pick_contract r g s` as is.
  - Locale and `spec/` are unchanged.

## Lessons / leads

- **Next lead on bmc: `certify`.** After the heap, `certify` (`reason_ok`, `force_var`,
  `force_trail`, `clause_exists`) is 46 % of the instructions on bmc-galileo-9 and ~33 % on
  galileo-8; memset (`cleared`) is 3 %.
- Inlining moves the hot loop. A small, never-executed addition (a `use_heap` branch whose callee
  gets inlined) cost +1.4 % instructions in `cdcl` on hole9. Compare instruction counts
  (deterministic) before timing, and keep cold code out of line with `#[inline(never)]`.
- `crush_base` needs a `const` used in an expression inlined (`HEAP_MIN_def`), like `BIG_def`.
- An `if c { self.call() }` before a loop doubles the loop goals: use
  `apply (all ‹ucincl_discharge…›)`.
- Pool Server: `Sat_Heap` checked fine. `Sat_Search` sat in its old slow proofs, so I used
  `isabelle-check` (7–8 min per pass, 4 passes).
- Scripts, archives and permuted copies were kept outside the worktree and deleted at the end.
