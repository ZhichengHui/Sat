- **Changes** (`core/src/lib.rs`; the design of #45 is kept: untrusted search, checked answers,
  `solve` as the fallback):
  1. clause-database reduction: `learnt_lbd` records each learned clause's literal block distance
     (LBD). Every 1000 + 500k conflicts, `reduce` (`count_live` → `cut` → `kill`) marks about half of the
     live learned clauses `dead`, the highest LBD first and the oldest first among equal ones;
     clauses of LBD ≤ 2 stay. `propagate_lit` drops a dead clause's node from the watch list it is
     visiting (`unlink`). Dead clauses stay in `learned`, so `learned_ok` and certification are
     untouched;
  2. `wkey`: the key of each watch node's literal, so a visit whose other watched literal is true
     does not read the clause (about 25 % faster on hole9);
  3. local learned-clause minimisation (`redundant`, `compact`, `unmark_from`, `minimize`): a
     literal whose reason's other literals are marked or of level 0 is dropped. A minimised
     clause still certifies, because `force_trail` forces those variables in trail order;
  4. activity increment decay 1/32 instead of 1/16 (VSIDS decay about 0.97).
  Tuning was done on hole9 and five randomly permuted copies (variable renaming, clause and
  literal order). Luby restarts were clearly worse (22–28 s on hole9). Without minimisation, or with
  decay 1/8 or 1/64, results were worse or noisier. Reductions every 2000 + 300k / 4000 + 1000k
  were slower.

- **Patterns / lessons**:
  - Code written to keep proofs cheap: one loop per function (`minimize`, `reduce` split into
    helpers), and guards instead of relational invariants (`i < len` before `i += 1` in
    `compact`; `left -= hist[t - 1]` before `t -= 1` in `cut`). After a call that takes
    `&mut self`, the state is unknown to the caller (its contract gives `∃ s'`), so `unlink` is
    called after the other writes to `next`/`head` in `propagate_lit`. Avoid `continue` (if/else
    chain instead).
  - A function whose first statement is a guarded update (`learnt_lbd`: `if tick < NONE { tick
    += 1 }`) makes `crush_base` produce two copies of the loop goal; the loop block is repeated.
  - Pool Server: the file of 1700 lines took about 1 min per heavy step under load (≈ 25 min for a
    pass), and it answered HTTP 500 from time to time. A scratch theory in `dev/` with only the new
    contracts and their dependencies (generated by a script from `Sat_CDCL.thy`) checked them in
    parallel in a few minutes. `isabelle-check` checked the whole project in 10 min. The pool's
    `isabelle_build_heap` builds on HOL only, so it cannot hold a heap of this project (its
    theories need AutoCorrode).
