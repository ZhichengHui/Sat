## How the time was found

- Command timings: Isabelle stores every command ≥ 0.1 s (`build_timing_threshold`) in the
  session database. A small Scala script (`Store.read_command_timings`,
  `Properties.uncompress`) printed them with symbol offsets, mapped to lines.
- Per goal: a `method_setup trace_all` (like Eisbach's `all`, but it times the method on each
  goal and appends `label #i time SOLVED/LEFT/FAIL :: conclusion` to a file) replaced every
  `apply (all …)` in an instrumented copy; a `dump_goals` method wrote the full goals. Warnings
  in the build database were not reliable for this (some theories had no `PIDE/messages`
  export); writing to a file was.
- Iterating on `Sat_CDCL` alone: a task heap of `Sat_Partial` … `Sat_Reduce` (5:22 at 8
  threads) and a session holding only the edited theory (2–11 min a pass).

## What was slow, and the fixes

All are proof-step orderings; no contract, `spec/` or `urust/` change, no shared lemma statement
changed. New helper lemmas: `learned_push_ok` (`Sat_CDCL`), `sok_learnt_push` (`Sat_Search`),
`clause_sat_nth` (`Sat_Certify`).

- **`sok_tac` (an `auto`) on goals that a rule proves directly.** In `on_conflict_spec` it took
  25 s for each `∃y. rvec_append_val (Search_lbd s) [x] = Some y` (`sok_lbd_dead`, applied in
  the *next* step, proves it), 6–9 s for `sok_in s` (`sok_asm`) and for `vok L24`/push goals on
  the learned clauses (`push_ok`), and failed for 12–15 s on each of 12 goals. Running
  `sok_asm`, `sok_lbd_dead` and `learned_push_ok` first left `sok_tac` < 0.1 s.
  `Search_analyze_clause_spec`: one push onto `learnt` took 72 s in `sok_tac`
  (`sok_learnt_push`). `Search_propagate_lit_spec`: `vok` after an element update 6 s each
  (`rule vok_update`), and `sok_tac` failed on the `mod 2` goals that `node_bound` closes, so
  `node_bound` now runs first.
- **`cdcl_bound`/`search_bound` failing on `sok` goals** (1–2 s each, 50–85 goals per proof):
  in `cdcl_spec`, `sok_asm` (which closed 52 of the 56 goals left) now runs first (cdcl_bound
  110 s → 13 s); in `Search_restart_due_spec`, `match conclusion in ‹sok _› ⇒ ‹sok_tac; fail›`
  before `search_bound`.
- **Broad `auto` on word bounds** (`Sat_Certify`): `unat r < n` from `r < word64_of_nat n`,
  `unat r < 2^64 - 1` from `r < y` took 4–35 s each; now `rule word64_less_of_nat
  word64_less_max, assumption`. `model_spec` and `clause_holds_spec` no longer need `auto`.

Pattern for next time: in a `(m; fail)?` cascade over all goals, the cost is mostly the
*failures* and the goals a cheaper later step would close. Put the cheap, specific steps
(`sok_asm`, `rule L; assumption`) first and the `auto`-based ones last.
